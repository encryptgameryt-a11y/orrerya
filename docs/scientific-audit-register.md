## 2. Current source and model conventions that must be preserved

- Sun mass share: 99.87% is the calculation for the Sun plus the eight planets only. NASA's approximate 99.85% is for a broader Solar System inventory. They have different denominators and are not competing estimates of the same ratio.
- Sun mass vs. GM: the Sun's displayed mass is a rounded NASA reference value. Use JPL's solar GM for orbital dynamics; do not infer a high-precision GM from rounded mass and G.
- CAI age: 4.56730 ± 0.00016 billion years dates a brief formation interval for some of the earliest accurately dated solids. It does not date the completion of planet formation.
- Planetary positions: the tool uses JPL approximate elements, including required Table 2b corrections for Jupiter through Neptune. The Earth element is the Earth–Moon barycentre. Browser local time is converted to UTC Julian date without full UTC-to-TDB conversion; results are geometric approximations, not apparent sky coordinates.
- Moon-derived values: mass is calculated as GM/G, density from mass and equivalent-volume radius, reference gravity from GM/r², and idealised spherical escape speed from sqrt(2GM/r). Input uncertainties are not propagated in the displayed point estimates.
- Oort Cloud: it is inferred from long-period comet orbits and dynamical models, not directly imaged as a bounded cloud. Its quoted extents are model estimates.
- Heliopause: it is a changing boundary of solar-wind influence, not the outer edge of the Sun's gravitationally bound region.
- Mission schedule: future dates are plans. Completed events require a dated source confirming completion.

## 3. Page-level audit still required

The following work is not claimed complete:

1. Re-check every numeric field and descriptive scientific claim on all eight planet profiles against the current NASA/JPL tables and relevant planet-specific research or mission pages.
2. Re-check every dwarf-planet parameter against the source table and the best available body-specific measurement literature; make uncertainties explicit where source quality permits.
3. Expand the satellite catalogue beyond the selected 22 entries only after choosing a defined scope and a reproducible catalogue snapshot. Do not present the selected page as a complete moon list.
4. Review every asteroid/comet/meteoroid definition and every named-body numerical claim against IAU definitions, NASA mission records and peer-reviewed sources.
5. Verify every distance range and population label on the Kuiper Belt, scattered disc, detached objects, Centaurs, Oort Cloud and heliosphere pages. Keep model estimates separate from observed spacecraft crossings.
6. Benchmark the planetary-position explorer against JPL Horizons at selected epochs, including modern dates and dates near the model's supported range. Current unit tests establish mathematical consistency but do not establish ephemeris accuracy.
7. Recheck all current and future mission milestones near each event. Juno is a specific example: NASA currently labels it active, while JPL's published extended-mission text says the funded extension ran through September 2025 or spacecraft end of life. Later 2026 trajectory products continue to document perijove operations. State the status source and date instead of treating a nominal funding date as a guaranteed end date.
8. Check every external image URL, image credit, processing/false-colour label, alt description and item-specific reuse conditions. A NASA-hosted file is not automatically NASA-owned.
9. Run real browser testing on current mobile and desktop browsers: navigation, interactive controls, keyboard access, focus order, screen-reader announcements, reduced motion, image loading, zoom and narrow-screen overflow.
10. Test the actual deployed response headers at the Cloudflare edge and inspect CSP reports/console behaviour. Repository header configuration alone does not prove every live response applies the intended policy.
11. Add automated link/image availability checks with sensible rate limits and a manual review path; an offline build check cannot guarantee external services remain online.

## 4. Release gate

Do not call ORRERYA scientifically complete merely because CI is green. The release gate is:

- all generated routes build and are present in the sitemap;
- lockfile-based installation is reproducible;
- physics and catalogue tests pass;
- critical claims have field-level sources, units, conventions and uncertainty notes;
- model tools are independently benchmarked;
- visual, keyboard and screen-reader QA is complete;
- mission and catalogue snapshots are dated and rechecked;
- production headers, canonical metadata and external imagery are verified after deployment.

A documented uncertainty or explicit unknown is preferable to an unsupported precise number.
